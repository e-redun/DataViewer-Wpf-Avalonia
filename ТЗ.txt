ТЗ на разработку пет-проекта "DataViewer"
1. Архитектура и стек технологийПлатформа:
.NET 10.0.Общая библиотека классов (Common): Чистая C# логика,
кроссплатформенная (TargetFramework: net10.0), хранит бизнес-модели,
логику доступа к данным и ViewModels.
Базовая MVVM библиотека: CommunityToolkit.Mvvm (с использованием Source Generators для свойств и команд).
UI-проекты (Дублированная разметка для сравнения технологий):
DataViewer.UI.Wpf (.NET 10.0 Windows)DataViewer.UI.Avalonia 
(.NET 10.0 Desktop — Windows/Linux/macOS)Именование (Каноны .NET): 
Строгий PascalCase для длинных аббревиатур в пространствах имен и классах
(например, DataViewer.UI.Wpf.Views, DatabasesViewModel, MainWindowViewModel).

2. Функциональные требования к интерфейсу (Главное окно)
Интерфейс представляет собой горизонтальную сетку (Grid) из 4 основных колонок
(Ряд 0) и нижней панели с кнопками (Ряд 1). 
Каждая колонка управляется своей изолированной ViewModel, 
а MainWindowViewModel выступает в роли главного координатора (дирижера):
Колонка 0 (DataBasesViewModel):
Отображает список подключенных баз данных.Перспектива: 
Поддержка баз данных разных типов через абстракцию (SQLite, PostgreSQL) — 
на старте фокусируемся на SQLite.
Колонка 1 (TablesViewModel):Отображает плоский список таблиц, 
принадлежащих выбранной в данный момент базе данных.
Колонка 2 (TableContentViewModel):Отображает табличное представление данных 
(строки и колонки) для выбранной таблицы. На первом этапе выводит ключевую колонку 
и связанные данные.Колонка 3 (PropertiesViewModel):
Аналог панели свойств (Properties Window) в IDE.
Отображает детальную информацию по выделенной строке (экземпляру) из TableContentViewModel.
Содержит умный селектор элементов управления (инпуты, переключатели, выпадающие списки) 
в зависимости от типов данных и атрибутов редактируемого поля.

3. Логика взаимодействия и потоки данных (Master-Detail)
Связывание компонентов происходит в MainWindowViewModel через обработку 
изменений выбранных состояний (методы On[Property]Changed):
Выбор БД \(\rightarrow \) Команда для TablesViewModel (загрузить список таблиц этой БД) 
+ Сброс последующих выборов.Выбор Таблицы \(\rightarrow \) 
Команда для TableContentViewModel (считать структуру колонок и вычитать строки из БД).
Выбор Строки/Экземпляра \(\rightarrow \) Передача объекта с данными в PropertiesViewModel 
для разбора свойств и их динамического отображения в правой панели.

4. Дополнительные технические задачи для прокачкиСравнение XAML:
Изучение отличий в реализации шаблонов данных (DataTemplate), стилизации и триггеров
(WPF Style.Triggers против CSS-подобных селекторов Avalonia).
Compiled Bindings: Использование строгой типизации привязок в Avalonia (x:DataType)
для ускорения рантайма и отлова ошибок на этапе компиляции.Общие ресурсы: 
Организация лаконичных XAML-структур для отступов (сокращенная запись Thickness) 
и изучение способов выноса констант в общий C# код.


Функциональное ТЗ: 
Приложение DataViewer
Интерфейс главного окна разделен на 4 вертикальные колонки (Master-Detail сценарий), 
где выбор в предыдущей колонке полностью меняет содержимое следующих.

1. Список баз данных (DataBasesViewModel)
Отображает список доступных баз данных.
На старте: Работаем локально с базой данных SQLite.
Перспектива: Архитектура пишется через общий интерфейс,
чтобы в будущем можно было в этот же список добавлять базы других типов (например, PostgreSQL).

2. Список таблиц (TablesViewModel)
Отображает плоский список всех таблиц, которые находятся внутри выбранной в первой колонке базы данных.
Если база данных не выбрана, список пуст.

3. Содержимое таблицы (TableContentViewModel)
Отображает данные (строки и колонки) из выделенной во второй колонке таблицы.
На первом этапе выводит ключевую колонку и связанные с ней данные в виде интерактивной таблицы.

4. Панель свойств (PropertiesViewModel)
Работает как окно «Свойства» (Properties) в Visual Studio или Rider.
Отображает детальную информацию по выделенному экземпляру (строке) 
из таблицы в третьей колонке.Умный интерфейс: 
Внутри панели работает селектор элементов управления. 
Он автоматически решает, как отображать поле для редактирования, 
в зависимости от типа данных и атрибутов (например: строка — обычное текстовое поле, 
логический тип — галочка-чекбокс, перечисление — выпадающий список).
